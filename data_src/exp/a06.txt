# 科目A 第6章 データベース の解説（初心者向け）

## p06-01
【この問題のポイント】
正規化は、表を分けて「同じデータを何か所にも持たない」ようにする作業です。
・関数従属「X → Y」：X が決まれば Y が1つに決まる
・部分関数従属：主キーの「一部」だけで決まる項目がある → 第2正規形で分ける
・推移的関数従属：主キー以外の項目で決まる項目がある → 第3正規形で分ける

【解き方】
① 主キーは {A, B}
② A → C：C は主キーの一部（A）だけで決まる → 部分関数従属。R2(A, C) に分ける
③ C → D：D は主キーではない C で決まる → 推移的関数従属。R3(C, D) に分ける
④ 残った主キーの組み合わせで R1(A, B)
→ R1(A, B)、R2(A, C)、R3(C, D)

【確かめ方】
R1 と R2 を A でつなぎ、R3 を C でつなげば、元の表が復元できます。

## p06-02
【この問題のポイント】
・第1正規形：1つのマスに1つの値（繰り返しの項目がない）
・第2正規形：さらに「主キーの一部だけで決まる項目」がない
・第3正規形：さらに「主キー以外の項目で決まる項目」がない

【解き方】
① 主キーは {受注番号, 商品番号} の組み合わせ
② 商品名と単価は「商品番号」だけで決まる → 主キーの一部で決まる（部分関数従属）がある
③ よって第2正規形ではない
④ 繰り返しの項目はないので、第1正規形ではある

## p06-03
【この問題のポイント】
SQL の処理は、次の順番で行われます。
① FROM：表を決める
② WHERE：条件に合う「行」に絞る（グループ化の前）
③ GROUP BY：同じ値ごとにまとめる
④ HAVING：まとめた「グループ」を条件で絞る（グループ化の後）

【解き方】
① WHERE 給与 >= 25：給与20の社員5が外れる
② GROUP BY 部署：営業（社員1、2）、開発（社員3、4）、総務（社員6）
③ HAVING COUNT(*) >= 2：2人以上のグループだけ残る → 営業、開発
④ 2行

【間違えやすい所】
WHERE を先に行うので、開発部は3人ではなく2人として数えます。

## p06-04
【この問題のポイント】
副問合せ（カッコの中の SELECT）が、外側の行（X）ごとに計算し直される形を「相関副問合せ」といいます。この問題では「その社員と同じ部署の平均給与」を、社員ごとに計算しています。

【解き方】
① 部署ごとの平均を出す
　営業：(30 ＋ 26) ÷ 2 ＝ 28
　開発：(40 ＋ 36 ＋ 20) ÷ 3 ＝ 32
　総務：28 ÷ 1 ＝ 28
② 自分の部署の平均より給与が「大きい」社員を選ぶ
　社員1（営業30 ＞ 28）○、社員2（26）×
　社員3（開発40 ＞ 32）○、社員4（36 ＞ 32）○、社員5（20）×
　社員6（総務28 ＝ 28）×（等しいだけで大きくない）
③ 1, 3, 4

## p06-06
【この問題のポイント】
SQL は順番に実行されるので、UPDATE で変えた後の値で SELECT が計算されます。

【解き方】
① UPDATE：区分A の価格を2倍にする
　商品1：100 → 200、商品2：200 → 400、商品3（区分B）：300 のまま
② SELECT：価格が300以上の行の合計
　400（商品2）＋ 300（商品3）＝ 700

## p06-07
【この問題のポイント】
関係演算の「射影」は、表から指定した「列」だけを取り出す操作です。関係データベースの理論では、表に同じ行は2つ存在できないので、射影した結果に重複した行があれば1つにまとめます。

【解き方】
部署の列だけを取り出すと「営業、営業、開発、開発、開発、総務」。重複を除くと 営業・開発・総務 の3行。

【間違えやすい所】
SQL の SELECT 部署 FROM 社員 は、DISTINCT を付けないと重複を除かず6行になります。理論上の射影と SQL の動きの違いに注意。

## p06-08
【この問題のポイント】
直積は、2つの表の行の「すべての組み合わせ」を作る演算です。

【解き方】
表R の各行（2行）に、表S の3行をそれぞれ組み合わせるので 2 × 3 ＝ 6行。

【例】
R が {a, b}、S が {1, 2, 3} なら a1, a2, a3, b1, b2, b3 の6行。

## p06-09
【この問題のポイント】
複数のトランザクションが同時に動くとき、データが矛盾しないように「ロック（鍵）」をかけます。2相ロック方式は、ロックの使い方を2つの段階（相）に分けるルールです。
・第1相：必要なロックを次々に獲得する（この間は1つも解放しない）
・第2相：ロックを解放していく（この間はもう獲得しない）
このルールを守ると、同時に実行しても、1つずつ順番に実行したのと同じ結果になります。

【ほかの選択肢】
・全てのサイトに問い合わせて一斉にコミット → 2相コミット（名前が似ているので注意）
・ロックの獲得と解放を任意の順番で → 2相ロックのルールを守っていない
・ロックをかけずにコミット時に検査 → 楽観的な方式

## p06-10
【この問題のポイント】
デッドロックは、お互いに相手が持っているロックを待ち合って、どちらも進めなくなる状態です。

【解き方】
① T1 が X をロックし、同時に T2 が Y をロックする
② T1 は次に Y が欲しいが、T2 が持っているので待つ
③ T2 は次に X が欲しいが、T1 が持っているので待つ
④ どちらも永遠に待ち続ける → デッドロック

【防ぎ方】
ロックする順番を全てのトランザクションで同じ（X → Y）にすれば起きません。

## p06-11
【この問題のポイント】
・コミット：トランザクションの更新を確定すること
・システム障害（電源断）：メモリの中の内容は消えるが、ディスクとログは残る
回復処理では、確定したものはやり直して反映し、確定していないものは取り消します。
・ロールフォワード：更新後の値（更新後ログ）を使って、更新をやり直す
・ロールバック：更新前の値（更新前ログ）を使って、更新を取り消す

【解き方】
① T1 はコミット済み → 結果を残す必要がある。ディスクに反映されていない可能性があるので、ロールフォワードする
② T2 はコミット前 → 途中の結果を残してはいけない。ロールバックする

## p06-12
【この問題のポイント】
同時に動くトランザクションどうしで起こる問題の名前を区別します。
・ダーティリード：まだコミットしていない（確定していない）更新を、他が読んでしまう。その更新が取り消されると、ありもしない値を読んだことになる
・ノンリピータブルリード：同じデータを2回読んだら、間に他が更新して値が変わっていた
・ファントムリード：同じ条件で2回検索したら、間に他が行を追加して件数が変わっていた

【解き方】
「コミットしていないデータを読む」のはダーティリードです。

## p06-13
【この問題のポイント】
索引（インデックス）は、本の巻末の索引と同じで、データを探しやすくするための仕組みです。

【解き方】
・検索：索引を使えば、全部の行を見なくても目的の行がすぐ見つかる → 速くなる
・追加・更新：表だけでなく索引も書き換える必要がある → 遅くなることがある
よって「検索は速くなるが、追加や更新は遅くなることがある」。

【ほかの選択肢】
・重複がなくなる → 索引にそういう働きはない
・行数が少ないほど効果が大きい → 逆。行数が多いほど効果が大きい

## p06-14
【この問題のポイント】
「1対多」の関係（1つの部署に多くの社員）を表で表すときは、「多」の側の表に、「1」の側の主キーを外部キーとして置きます。

【解き方】
① 社員1人は部署1つに所属 → 社員の表に「部署コード」の列を1つ置けば足りる
② 部署の表に社員番号を置こうとすると、1つの部署に社員が何人もいるので、1つのマスに複数の値が必要になってしまう（第1正規形に反する）
→ 表「社員」に部署コードを外部キーとして置く

## p06-15
【この問題のポイント】
NoSQL は、大量のデータを多くのサーバに分けて保存することが多いデータベースです。全てのサーバの内容を常に一致させようとすると遅くなるので、「結果整合性」という考え方をとります。
・結果整合性：更新した直後はサーバによって内容が違うことがあるが、少し時間がたてば最終的に全部一致する

【ほかの選択肢】
・トランザクションの途中を他から見えなくする → ACID の独立性
・コミットしたデータは障害でも失われない → ACID の永続性
・全てを1台に保存する → 分散しない形で、NoSQL の特徴ではない

## p06-16
【この問題のポイント】
ETL は、分析のためにデータを集める処理の3段階の頭文字です。
・Extract（抽出）：いろいろなシステムからデータを取り出す
・Transform（変換）：形式をそろえたり、きれいにしたりする
・Load（書込み）：データウェアハウス（分析用の倉庫）に入れる

【ほかの選択肢】
・OLTP：日々の取引をその場で処理する（オンライントランザクション処理）
・CRUD：データの基本操作 Create（作成）・Read（読取り）・Update（更新）・Delete（削除）
・レプリケーション：データの複製を別のサーバに作る

## p06-17
【この問題のポイント】
SQL の LIKE は、文字のパターンで検索します。
・%：0文字以上の何でもよい文字列
・_：ちょうど1文字の何でもよい文字
'%藤' は「何文字かの後に、最後が藤」＝「藤で終わる」という意味です。

【解き方】
・佐藤 → 藤で終わる ○
・加藤 → 藤で終わる ○
・佐々木 → ×
・伊藤太郎 → 藤の後に「太郎」が続く ×
・藤井 → 藤で始まる ×
→ 2行

## p06-18
【この問題のポイント】
外部キーは、他の表の主キーを参照する列です。参照先の行を削除したときに、参照している行をどうするかを指定できます。
・ON DELETE CASCADE：参照している行も一緒に削除する（連鎖して削除）
・ON DELETE SET NULL：参照している列を NULL（空）にする
・RESTRICT／NO ACTION：参照している行があれば、削除できない（エラー）

【解き方】
CASCADE なので、部署を削除すると、その部署の社員の行も自動的に削除されます。

## p06-19
【この問題のポイント】
ビューは、元の表（基底表）から作る「見え方」だけの仮想の表です。データを別に持っているわけではありません。

【解き方】
・見せたい列や行だけのビューを作り、利用者にはビューだけを使わせれば、見せたくない情報を隠せる → 正しい

【ほかの選択肢】
・データを複製して保存 → ビューはデータを持たない。元の表を更新すれば、ビューの内容も変わる
・SELECT 文を実行できない → ビューは SELECT で検索するためのもの
・1つの表からしか作れない → 複数の表を結合して作ることもできる
