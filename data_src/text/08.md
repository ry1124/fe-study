## 第8章 情報セキュリティ

情報を守るための考え方、攻撃の種類と対策、暗号と電子署名の仕組みを学びます。

> **この章のゴール**
> ・攻撃の名前を聞いて、どんな攻撃か・どう防ぐかを言える
> ・公開鍵暗号と電子署名で、どの鍵を使うか分かる
> ・ファイアウォール、DMZ、WAF などの対策を区別できる
> 科目Aで10問前後、科目Bでも4問出ます。

### ① 情報セキュリティの3つの要素

| 要素 | 意味 | 損なわれる例 |
| --- | --- | --- |
| 機密性 | 許された人だけが見られる | 情報漏えい |
| 完全性 | 内容が正しく、書き換えられていない | 改ざん |
| 可用性 | 必要なときに使える | サーバが止まる |

> **覚え方**：英語の頭文字で「CIA」（Confidentiality・Integrity・Availability）。

#### リスクへの対応
危険（リスク）への対応は4種類です。
| 対応 | 意味 | 例 |
| --- | --- | --- |
| 低減 | 起こりにくく、被害を小さくする | ウイルス対策ソフトを入れる |
| 回避 | 危ないことをやめる | 危険な事業から撤退する |
| 移転（共有） | 他の人に負担してもらう | 保険に入る、外部に任せる |
| 保有（受容） | 何もせず受け入れる | 被害が小さいので対策しない |

### ② 攻撃の種類と対策

#### Webサイトへの攻撃
| 攻撃 | どんな攻撃？ | 対策 |
| --- | --- | --- |
| SQLインジェクション | 入力欄に SQL の命令を入れて、データベースを勝手に操作する | **プレースホルダ**（入力を命令として扱わない仕組み） |
| クロスサイトスクリプティング（XSS） | 掲示板などに悪いプログラム（スクリプト）を書き込み、見た人のブラウザで動かす | 画面に出すとき、「<」などの記号を無害な文字に置き換える（**エスケープ**） |
| クロスサイトリクエストフォージェリ（CSRF） | ログイン中の人に罠のページを見せて、勝手に書き込みや購入をさせる | 重要な操作の前にパスワードを再入力させる、合言葉（トークン）を使う |
| ディレクトリトラバーサル | 「../」を使って、見せてはいけないファイルを読む | ファイル名を直接指定させない |

#### パスワードへの攻撃
| 攻撃 | どんな攻撃？ | 対策 |
| --- | --- | --- |
| ブルートフォース攻撃 | パスワードを総当たりで試す | 何回か間違えたらロック |
| パスワードリスト攻撃 | 他のサイトから漏れた ID とパスワードの組をそのまま試す | **パスワードを使い回さない**、多要素認証 |
| レインボーテーブル攻撃 | よくあるパスワードとハッシュ値の対応表で推測する | **ソルト**（ランダムな文字）を付けてからハッシュ化する |

#### その他の攻撃
| 攻撃 | どんな攻撃？ |
| --- | --- |
| DoS／DDoS攻撃 | 大量のアクセスでサービスを止める（DDoS は多数の機器から） |
| 標的型攻撃 | 特定の会社を狙って、ウイルス付きのメールを送る |
| 水飲み場型攻撃 | 狙う人がよく見るサイトを書き換えて、罠を仕掛けておく |
| ゼロデイ攻撃 | 弱点（脆弱性）の修正が出る前に攻撃する |
| フィッシング | 本物そっくりの偽サイトに誘導して、パスワードなどを入力させる |
| ソーシャルエンジニアリング | 電話でなりすます、のぞき見るなど、人の心のすきを突く |
| ビジネスメール詐欺 | 取引先になりすまして、偽の口座にお金を振り込ませる |

#### マルウェア（悪いプログラム）
- **ランサムウェア**：ファイルを勝手に暗号化し、戻す代わりにお金を要求する
- **ボット**：感染したパソコンを、攻撃者が遠くから操る
- **ワーム**：自分で自分をコピーして広がる
- **トロイの木馬**：役に立つソフトのふりをして入り込む
- **スパイウェア**：こっそり情報を集めて送る

### ③ 暗号

#### イメージ
暗号は、データに「鍵」をかけて、鍵を持つ人だけが読めるようにする仕組みです。

#### 共通鍵暗号
- かけるときと開けるときに**同じ鍵**を使う
- 処理は速いが、相手に鍵を安全に渡すのが難しい
- 相手ごとに別の鍵が必要。n人なら n(n−1)÷2 本
- 例：AES

#### 公開鍵暗号
- 1人が**2つの鍵**を持つ。「**公開鍵**」（みんなに配る）と「**秘密鍵**」（自分だけが持つ）
- 片方の鍵でかけたものは、もう片方の鍵でしか開けられない
- 例：RSA

#### 例題：A さんが B さんに、秘密の手紙を送る
① B さんの**公開鍵**で暗号化する（誰でも B さんの公開鍵は手に入る）
② B さんの**秘密鍵**でしか開けられないので、B さんだけが読める

> **覚え方**：暗号化は「**受け取る人の公開鍵**」でかける。

### ④ ハッシュと電子署名

#### ハッシュ関数
どんな長さのデータからも、決まった長さの値（**ハッシュ値**）を作る計算です。
- 元のデータに戻すことはできない
- データが1文字でも変わると、ハッシュ値は全く違う値になる
→ データが**改ざんされていないか**を確かめるのに使う

#### 電子署名（デジタル署名）
「本人が送ったこと」と「改ざんされていないこと」を確かめる仕組みです。
① 送る人：データのハッシュ値を、**自分の秘密鍵**で暗号化して付ける（これが署名）
② 受け取る人：署名を**送った人の公開鍵**で戻し、自分で計算したハッシュ値と比べる
③ 一致すれば、本人が送り、途中で書き換えられていないと分かる

> **覚え方**：署名は「**自分の秘密鍵**」で付け、「**送った人の公開鍵**」で確かめる。暗号化と逆になる。

#### 認証局（CA）とデジタル証明書
「この公開鍵は、確かにこの人（会社）のものです」と証明する機関が**認証局**です。認証局が発行する証明書を**デジタル証明書**といいます。有効期限の前に無効になった証明書は、**CRL**（失効リスト）で公開されます。

### ⑤ 認証（本人確認）

#### 認証の3つの要素
| 要素 | 例 |
| --- | --- |
| 知識（知っていること） | パスワード、秘密の質問 |
| 所持（持っているもの） | スマートフォン、ICカード |
| 生体（体の特徴） | 指紋、顔、静脈 |

**多要素認証**は、**違う種類の要素**を2つ以上組み合わせます。
- パスワード ＋ スマホに届く確認コード → 知識 ＋ 所持 で多要素 ○
- パスワード ＋ 秘密の質問 → 知識 ＋ 知識 で多要素ではない ×

#### その他の認証
- **シングルサインオン**：1回ログインすれば、複数のシステムを使える
- **リスクベース認証**：いつもと違う場所や端末からのログインのときだけ、追加の確認をする
- **CAPTCHA**：ゆがんだ文字などで、人間かプログラムかを見分ける

### ⑥ 守るための技術

| 技術 | 役割 | たとえ |
| --- | --- | --- |
| ファイアウォール | 通信を、送り先・ポート番号などで通す／止める | 建物の入口の警備員 |
| DMZ | インターネットと社内の間に作る中間の区域。公開するサーバ（Webサーバなど）を置く | 来客用の応接室 |
| WAF | Webサイトへの通信の**中身**を見て、攻撃を止める | 荷物の中身まで調べる検査 |
| IDS | 怪しい通信を見つけて知らせる | 防犯カメラ |
| IPS | 怪しい通信を見つけて止める | 防犯カメラ ＋ 警備員 |
| VPN | インターネット上に暗号化した専用の通り道を作る | 専用トンネル |
| TLS（HTTPS） | Web の通信を暗号化し、サーバが本物か確かめる | 封をした手紙 |

> **間違えやすい所**：IDS は「見つけて知らせる」だけ、IPS は「止める」まで行う。

### ⑦ 管理の仕組み

- **情報セキュリティポリシー**：会社の情報を守る決まり。「基本方針」「対策基準」「実施手順」の3段階
- **ISMS**：情報セキュリティを、計画・実行・確認・改善（PDCA）で管理する仕組み
- **CSIRT**：セキュリティ事故（インシデント）に対応する社内のチーム
- **最小権限**：仕事に必要な最小限の権限だけを与える
- **ゼロトラスト**：社内のネットワークも信用せず、アクセスのたびに確認する考え方

#### 事故が起きたときの最初の行動
ウイルスに感染したかもしれないときは、
① まず**ネットワークから切り離す**（LANケーブルを抜く）→ 被害が広がらないように
② 電源はすぐに切らない → 調査のための記録が消えるから
③ 担当部署に報告する

### この章のまとめ

- 機密性（見られない）、完全性（書き換えられない）、可用性（使える）
- SQLインジェクション → プレースホルダ、XSS → エスケープ、パスワードリスト攻撃 → 使い回さない
- 暗号化は受け取る人の公開鍵、電子署名は自分の秘密鍵（確かめるのは送った人の公開鍵）
- ハッシュは改ざんの確認に使う。元に戻せない
- 多要素認証は、違う種類の要素を組み合わせる
- DMZ には公開サーバを置く。WAF は中身を見る。IDS は知らせる、IPS は止める
- 感染したら、まずネットワークから切り離す
