## 第12章 科目B 情報セキュリティの解き方

科目Bの最後の4問は、会社で起きたセキュリティの出来事（事例）を読んで、原因や対策を選ぶ問題です。その解き方を学びます。

> **この章のゴール**
> ・長い事例文から、問題の原因を見つけられる
> ・「その原因に効く対策」を選べる
> ・1問5分以内で解ける
> プログラムは出ません。第8章の知識と、「読み取る力」で解けます。ここで時間を節約して、アルゴリズムの問題に回すのが作戦です。

### ① どんな問題が出る？

#### 例
「A社の社員が、取引先を名乗るメールの添付ファイルを開いたら、パソコンの動きがおかしくなった。社員が最初にすべきことはどれか。」
このように、具体的な会社の出来事が書かれていて、
- 最初にすべき行動
- 原因
- 再発を防ぐ対策
- ルールに違反しているもの
などを選びます。

### ② 解き方の手順

1. **いちばん最後の設問（問い）を先に読む**
　→ 何を聞かれているか（初動？原因？対策？）を先に知っておくと、読むべき所が分かる
2. **本文を読み、「何が起きたか」「どこが弱かったか」に印を付ける**
　→ 問題文に、ヒントは必ず書いてある
3. **選択肢を、「事例の問題を解決するか」で消していく**
　→ 一般的には正しくても、この事例の問題に効かない選択肢は不正解

> **間違えやすい所**：「パスワードを複雑にする」「ログを保存する」などは、一般的にはよい対策です。でも、事例の原因と関係なければ不正解になります。

### ③ よく出るテーマと正解の考え方

| テーマ | 正解になりやすい考え方 |
| --- | --- |
| ウイルス感染の最初の行動 | まず**ネットワークから切り離す**。電源はすぐに切らない（調査の記録が消える）。担当部署に報告する |
| メールの誤送信 | 送る前に確認・一時保留する。たくさんの人に送るときは **BCC** を使う |
| なりすましメール・振込先の変更 | メールに返信せず、**別の方法（電話など）で確認**する |
| パスワード | **使い回さない**、多要素認証、何回か間違えたらロック |
| アクセス権 | **必要な人に必要な分だけ**（最小権限）。異動・退職したらすぐに権限を削除。定期的に見直す（棚卸し） |
| パソコン・USBメモリの紛失 | 中身を**暗号化**しておく。なくしたら遠隔で消す |
| 外部の会社に仕事を任せる | 契約で秘密を守る・勝手に再委託しないことを決め、定期的に確認する |
| 脆弱性（ソフトの弱点） | 修正プログラムを早く当てる。どんな機器があるか一覧で管理する |
| バックアップ | **ネットワークから切り離した場所**にも保管する（ランサムウェア対策）。戻せるか試しておく |
| テレワーク | VPN、多要素認証を使う |

### ④ 迷ったときの考え方

- 「その対策をしていれば、**この事例で起きたことを防げたか**？」と考える
- 「全部禁止する」のように**仕事が止まってしまう対策**は、ふつう正解にならない
- 「技術的な対策」を聞いているのか、「人やルールの対策」を聞いているのか、設問をよく読む

### ⑤ 例題で練習

#### 事例
「B社では、退職した社員のアカウントが削除されずに残っていた。退職の手続きは人事部で行われるが、情報システム部には連絡が来ない仕組みだった。」

#### 問い
再発を防ぐ対策として、最も適切なものは？

#### 考え方
① 何が起きた？ → 退職者のアカウントが残っていた
② なぜ？ → 退職の情報が、情報システム部に伝わる仕組みがない
③ 原因に効く対策 → 退職の手続きの中に「アカウント削除の依頼」を組み込み、さらに定期的にアカウントの一覧を見直す
④ 「パスワードを毎月変える」などは、原因（伝わらない仕組み）を解決しないので不正解

### この章のまとめ

- 設問を先に読み、何を聞かれているかを知る
- 本文から「何が起きたか」「なぜ起きたか」を探す
- 原因に効く対策を選ぶ。一般論として正しいだけの選択肢に注意
- 感染したらネットワークから切り離す。なりすましは別の方法で確認。バックアップは切り離した場所にも
