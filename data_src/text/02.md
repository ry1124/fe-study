## 第2章 データ構造とアルゴリズムの基本

データをどう並べてしまっておくか（データ構造）と、どういう手順で処理するか（アルゴリズム）の基本を学びます。

> **この章のゴール**
> ・スタックとキュー、木、リストの動きを説明できる
> ・2分探索がなぜ速いか分かる
> ・主なソート（並べ替え）の名前とやり方を結び付けられる
> 科目Aでも出ますが、それ以上に**科目Bのプログラムを読む土台**になります。

### ① データ構造ってなに？

#### イメージ
同じ本でも、本棚に番号順に並べるか、机に積み重ねるかで、取り出しやすさが変わります。データも同じで、どう並べておくかによって、探しやすさや追加しやすさが変わります。この「並べ方」をデータ構造といいます。

### ② 配列

#### イメージ
番号の付いたロッカーです。「5番のロッカー」とすぐに開けられます。

- 番号（**要素番号**、添字）で、どの場所にもすぐアクセスできる
- 途中に新しいデータを入れるには、後ろを全部1つずつずらす必要があるので遅い

#### 2次元配列
表のように、行と列の2つの番号で場所を決める配列です。A[2, 3] は「2行目の3列目」。

### ③ スタックとキュー

#### スタック（後入れ先出し：LIFO）
**イメージ**：積み重ねたお皿。最後に載せたお皿から取ります。
- 積む操作を **push**、取り出す操作を **pop** という
- 使われる所：関数の呼び出しの管理、「元に戻す」機能、逆ポーランド記法の計算

#### キュー（先入れ先出し：FIFO）
**イメージ**：お店のレジの行列。先に並んだ人から順に会計します。
- 後ろに入れる操作を **enqueue**、前から取り出す操作を **dequeue** という
- 使われる所：処理の順番待ち、プリンタの印刷待ち

#### 例題：スタックの動き
空のスタックに、push 1 → push 2 → pop → push 3 → pop → pop の順に操作すると、取り出される順は？
| 操作 | スタックの中（右が一番上） | 取り出した値 |
| --- | --- | --- |
| push 1 | 1 | |
| push 2 | 1 2 | |
| pop | 1 | 2 |
| push 3 | 1 3 | |
| pop | 1 | 3 |
| pop | （空） | 1 |
答え：2、3、1

> **覚え方**：スタックは「お皿（後から来たものが先）」、キューは「行列（先に来たものが先）」。

### ④ 連結リスト

#### イメージ
宝探しのメモのように、各データが「次のデータはここにあるよ」という矢印（**ポインタ**）を持ってつながっている形です。

- 途中に追加・削除するときは、矢印を付け替えるだけでよいので速い
- 何番目のデータかを知るには、先頭から順にたどる必要がある

#### 途中に追加する手順（X の後ろに Y を入れる）
① Y の矢印を、X の次のデータに向ける（Y.next ← X.next）
② X の矢印を Y に向ける（X.next ← Y）

> **間違えやすい所**：順番を逆にすると、②で X の矢印を書き換えた時点で、元の次のデータが分からなくなります。

#### 削除する手順（X の次の要素を消す）
X の矢印を、消したい要素を飛ばしてその次に向けます（X.next ← X.next.next）。

#### いろいろなリスト
- **双方向リスト**：前のデータへの矢印も持つ。前にも後ろにもたどれる
- **循環リスト**：最後のデータの矢印が先頭に戻る

### ⑤ 木構造

#### イメージ
会社の組織図や、家系図のような形です。一番上を**根**、枝分かれした先を**子**、子のない一番下を**葉**といいます。

#### 2分木
どの節（丸）も、子が2つまでの木です。

#### 2分探索木
「**左の子孫は自分より小さく、右の子孫は自分より大きい**」というルールの2分木です。探すときは、根から「小さければ左、大きければ右」と進むので、全部を見なくて済みます。

例：40 が根で、20（左）、60（右）。30 を探すと、40 → 20 → 30 と3回で見つかります。

#### ヒープ
「**親は子以上**（または以下）」というルールの木です。一番大きい（小さい）値が、いつも根にあります。
配列で表すことが多く、要素番号 i の子は **2i と 2i＋1**、親は **i ÷ 2（切捨て）** です。

#### 木のなぞり方（3種類）
| なぞり方 | 順番 | 覚え方 |
| --- | --- | --- |
| 先行順 | 自分 → 左 → 右 | 自分が「先」 |
| 中間順 | 左 → 自分 → 右 | 自分が「中」 |
| 後行順 | 左 → 右 → 自分 | 自分が「後」 |

> **覚え方**：2分探索木を中間順でなぞると、**小さい順**に並ぶ。

### ⑥ 探索（探す方法）

| 方法 | やり方 | 速さ |
| --- | --- | --- |
| 線形探索 | 先頭から順番に1つずつ調べる | 遅い（平均で全体の半分を調べる） |
| 2分探索 | 並んだデータの真ん中と比べ、範囲を半分にしていく | とても速い |
| ハッシュ探索 | 計算式で、データの置き場所を直接求める | 最も速い（1回で見つかることが多い） |

#### 2分探索のイメージ
辞書で単語を引くとき、真ん中あたりを開いて「もっと前か、後ろか」で半分ずつ絞りますね。それと同じです。
- **前提：データが小さい順（大きい順）に並んでいること**
- 1回比べるごとに範囲が半分になる。1,000個なら約10回、100万個でも約20回で見つかる

#### ハッシュ
データ（キー）から計算した値（**ハッシュ値**）を、置き場所の番号にします。例：「キーを10で割った余り」。違うキーが同じ場所になることを**衝突**（シノニム）といい、そのときは空いている次の場所を使うなどの工夫をします。

#### 番兵
線形探索で、探す値を配列の最後にわざと置いておく方法です。必ず見つかるので、「配列の終わりまで来たか」を毎回確かめなくて済みます。

### ⑦ ソート（並べ替え）

| 名前 | やり方 | 速さ |
| --- | --- | --- |
| バブルソート | 隣どうしを比べ、逆なら入れ替える。1周で最大値が一番後ろに行く | 遅い |
| 選択ソート | まだ並べていない中から最小値を探し、先頭と入れ替える | 遅い |
| 挿入ソート | 1つずつ取り出し、並べ終わった部分の正しい位置に差し込む | 遅い（ほぼ並んでいれば速い） |
| クイックソート | 基準値より小さいグループと大きいグループに分けることを繰り返す | 速い（最悪は遅い） |
| マージソート | 半分に分けて並べ、2つを合わせる（併合）ことを繰り返す | 速い（作業用の場所が必要） |
| ヒープソート | ヒープを作り、根（最大値）を取り出していく | 速い |

#### 例題：バブルソートの1周目
{5, 1, 4, 2, 8} を小さい順にする。隣どうしを左から比べる。
| 比べる | 結果 |
| --- | --- |
| 5 と 1 → 入れ替え | {1, 5, 4, 2, 8} |
| 5 と 4 → 入れ替え | {1, 4, 5, 2, 8} |
| 5 と 2 → 入れ替え | {1, 4, 2, 5, 8} |
| 5 と 8 → そのまま | {1, 4, 2, 5, 8} |

#### 安定なソート
同じ値のデータが、並べ替えた後も元の順番のままになるソートを「安定」といいます。
- 安定：バブル、挿入、マージ
- 安定でない：選択、クイック、ヒープ

### ⑧ 計算量（速さの表し方）

データの量 n が増えたとき、処理の回数がどう増えるかを **O（オーダー）記法** で表します。

| 表し方 | 意味 | 例 |
| --- | --- | --- |
| O(1) | データが増えても回数は同じ | ハッシュ探索 |
| O(log n) | データが2倍になっても1回増えるだけ | 2分探索 |
| O(n) | データに比例して増える | 線形探索 |
| O(n log n) | n より少し多い | クイック・マージ・ヒープソート |
| O(n²) | データが2倍で回数は4倍 | バブル・選択・挿入ソート |

> **覚え方**：「繰り返しの中に繰り返し」なら n²。「毎回半分にする」なら log n。

### ⑨ 再帰

#### イメージ
マトリョーシカ人形のように、関数の中で**自分自身を呼び出す**ことです。大きな問題を、同じ形の小さな問題に分けて解きます。

#### 例：階乗
5! ＝ 5 × 4 × 3 × 2 × 1 は、「5 × (4!)」と書けます。
- f(n) ＝ n × f(n − 1)
- f(1) ＝ 1（ここで止まる。これを**終了条件**という）

f(3) ＝ 3 × f(2) ＝ 3 × 2 × f(1) ＝ 3 × 2 × 1 ＝ 6

> **間違えやすい所**：終了条件がないと、永遠に自分を呼び続けて止まりません。

### この章のまとめ

- スタックは後入れ先出し（お皿）、キューは先入れ先出し（行列）
- リストは矢印でつながる。追加は「新しい方の矢印を先に」
- 2分探索木は左が小さく右が大きい。中間順で小さい順
- ヒープの子は 2i と 2i＋1、親は i÷2
- 2分探索は並んでいることが前提。範囲を半分ずつにするので O(log n)
- ソートの名前とやり方を結び付ける。安定なのはバブル・挿入・マージ
- 再帰は自分自身を呼ぶ。終了条件が必要
